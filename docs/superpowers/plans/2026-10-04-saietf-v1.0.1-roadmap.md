# SaiETF V1.0.1 Delivery Roadmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a cloud-built, installable SaiETF V1.0.1 Android APK with the frozen TF Asset V3.7.8 finance core, local-first portfolio management, market wall, automatic dividends, page editor, Widget, overlay, notifications, encrypted backup, and GitHub Release artifacts.

**Architecture:** Build the empty repository as a Kotlin/Jetpack Compose multi-module Android project. Implement six gated phases; each phase consumes only published interfaces from earlier phases, pushes directly to `main`, and must leave CI green before the next phase starts.

**Tech Stack:** AGP 9.4.0, Gradle 9.6.0, Kotlin 2.4.20, JDK 17, compile/target SDK 36, min SDK 29, Compose BOM 2026.09.00, Room 2.8.5, Navigation 2.9.6, Glance 1.2.0, WorkManager, Coroutines/Flow, JUnit, Compose UI Test, Android Emulator, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-04-saietf-android-design.md`

## Global Constraints

- Package is `tw.saietf.app`; `versionName=1.0.1`; `versionCode=10001`.
- Develop directly on `main`; do not create PRs and do not submit to Google Play during development.
- User finance data remains local; GitHub stores source, CI, build logs, tests, APKs, hashes, SBOM, and releases only.
- Never commit provider keys, signing keys, backup passwords, or user portfolio data.
- TF Asset finance behavior is frozen at `a872644c572d24fc5ffe597a97eb6d7d8bd7283f`.
- TF Asset editor behavior is referenced at `8fc58cd00f0e1c7df24fc0ae437c098bfdaf2f80`.
- Kotlin finance results must exactly equal the frozen TypeScript fixtures; no tolerance is allowed for integer outputs.
- Traditional Chinese is the primary language; symbols use Chinese names or Chinese short names.
- Every commit runs CI; a failing phase blocks all later phases and all releases.
- Every user-visible success message must reflect a committed result, not an attempted operation.

## Review Focus

- A correction or retry must not duplicate ledger rows, daily snapshots, dividends, or notifications; owning tests live in Phases 2, 4, and 6.
- A new Taipei trading day must reject stale prior-session quotes even when the stale source has more fields; owning tests live in Phase 3.
- Process death between write steps must leave either the old valid state or the complete new state; owning tests live in Phases 2, 4, 5, and 6.
- A malformed editor or backup payload must fail closed without crashing a runtime page or partially replacing the database; owning tests live in Phases 5 and 6.
- Android background restrictions must never silently claim that Widget, overlay, or notification data is live when the service did not run; owning tests live in Phase 6.
