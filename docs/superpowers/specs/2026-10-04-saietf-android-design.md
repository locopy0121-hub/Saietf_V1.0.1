## 1. 目標與範圍

SaiETF 是一套完全獨立、可安裝的台股與台灣 ETF 資產管理 App。新 App 不沿用 TF Asset 的 UI、行情、AI、頁面、設定或使用者資料，但帳務核心必須由已定版的 TF Asset Canonical Finance Core V3.7.8 等價移植，版面編輯器則參照目前 TF Asset 頁面設定工具的能力模型與操作流程。第一版必須同時具備：

- 不限數量的實際與模擬自訂組合。
- 買入、賣出、費稅、庫存批次與完整交易紀錄。
- 台股與台灣 ETF 行情中心及首頁持股行情牆。
- 總資產、昨日損益、今日損益、持有總損益、已實現損益與含息報酬。
- 每日資產快照與歷史統計。
- 自動更新的股息月曆。
- Android 桌面 Widget、即時行情浮動視窗與每日損益通知。
- 具真實預覽、元件選取及手風琴工具列的版面編輯器。
- 本機加密資料庫與可匯出的加密備份。
- 可安裝 APK、SHA-256、版本資訊與驗收報告。

App 第一語系為繁體中文，標的名稱顯示中文名稱並可使用中文簡稱。

## 2. 雲端開發與資料邊界

### 2.1 GitHub 為開發主平台

- 所有程式碼、設計規格、測試、CI 設定、建置記錄與 Release 都保存於 GitHub。
- 開發期間直接提交到 `main`，不建立 Pull Request，不送人工 Code Review，也不提交 Google Play 商店審核。
- 每次推送仍必須執行自動化測試、Lint、Debug／QA APK 建置與成品雜湊驗證。
- 通過 Release Gate 後，APK、SHA-256、測試摘要與版本清單上傳 GitHub Release。
- 行情供應商憑證與簽署憑證只能存放於 GitHub Actions Secrets，不得寫入 Repo 或 APK 原始碼。
- 所有依賴版本固定於 Version Catalog 與 lockfile，確保雲端建置可重現。

### 2.2 使用者資料維持本機優先

「雲端作業」只適用於開發、建置與發佈。使用者的交易、庫存、股息、組合及損益資料不會上傳 GitHub，也不要求建立雲端帳號。Runtime 資料以手機內的加密資料庫為唯一帳務真相，使用者只能透過加密備份檔主動匯出或還原。

## 3. 技術架構

採原生 Android 分層架構：

1. **UI 層**：Jetpack Compose、Navigation、Glance Widget。
2. **Domain 層**：帳務、庫存、組合、損益、股息、行情新鮮度與分析規則。
3. **Data 層**：Room SQLite、加密層、Repository、行情與公告來源轉接器。
4. **Platform 層**：WorkManager、前景服務、浮動視窗、通知、Android Keystore、Storage Access Framework。

模組邊界：

| 模組 | 單一責任 |
|---|---|
| `core-ledger` | 不可變交易帳本、費稅、庫存批次與現金紀錄 |
| `core-portfolio` | 實際／模擬組合、配置、績效、風險與再平衡 |
| `core-market` | 行情來源、正規化、新鮮度、快取與熔斷 |
| `core-pnl` | 今日、昨日、持有、已實現、含息與每日快照 |
| `core-dividend` | 股息公告同步、事件狀態、月曆與入帳 |
| `feature-dashboard` | 總資產、行情牆、資產走勢、組合摘要與近期事件 |
| `feature-portfolios` | 組合清單、詳情、比較、模擬與分析建議 |
| `feature-transactions` | 交易新增、沖銷、更正、清單與分頁 |
| `feature-dividends` | 股息月曆、清單、事件詳情與統計 |
| `feature-layout-editor` | 真實預覽、元件能力、版面草稿、套用、取消與重設 |
| `feature-settings` | Widget、浮動視窗、通知、備份、來源與系統設定 |
| `platform-surfaces` | Widget、通知、前景服務與浮動視窗 |

UI 不直接讀取外部 API 或直接計算帳務；只透過 Use Case 與 Repository 取得已驗證資料。

## 4. TF Asset 核心與編輯器移植邊界

### 4.1 Canonical Finance Core 來源鎖定

帳務移植唯一來源：

- Repo：`locopy0121-hub/ETF-Finance-Manager-V3.7`
- Commit：`a872644c572d24fc5ffe597a97eb6d7d8bd7283f`
- 版本語意：V3.7.8 Immutable Canonical Finance Core
- 主要核心：`src/utils/etfCalculators.ts`、Broker Profile 契約、Ledger 投影與相關型別
- 驗收來源：`ACCOUNTING_GOLDEN_00878.cjs`、`ACCOUNTING_CONTRACT_TEST.cjs`、`BREAKING_HUANAN_CORE_TEST.cjs`、`CASH_LEDGER_CONTRACT_TEST.cjs` 及 V3.7.8 已通過的金融測試

移植採「行為等價」而非重新設計：將 TypeScript Canonical Core 轉為 Kotlin Domain Core，輸入、輸出、公式順序、取整、費稅、成本釋放與損益定義必須一致。不得以 Kotlin 慣例、Decimal API 或新版需求為理由自行變更結果。

### 4.2 V3.7.8 不可改寫規則

- 手續費率 `0.001425`，預設折扣 `0.65`。
- `ODD_LOT`／定期定額最低手續費 `1` 元；`ROUND_LOT` 最低手續費 `20` 元。
- ETF 賣出證交稅率 `0.001`；一般股票 `0.003`。
- 成交金額、手續費、證交稅、目前市值、股息總額與二代健保補充保費皆依核心位置使用 `Math.floor` 等價規則。
- 買進含費成本：`floor(price × shares) + fee`。
- `actualFee` 與 `actualTax` 一旦存在即為歷史真值，不得再疊加估算值，也不得因券商設定變更重寫。
- 持倉採含買進費用的移動平均成本；部分賣出只釋放對應股數成本，不使用賣出所得反向沖減剩餘成本。
- 賣出淨收入為成交金額減實際／估算手續費與實際／估算證交稅；已實現損益為淨收入減釋放成本。
- 毛市值、預估淨清算價值、未實現損益、已實現損益、淨股息與綜合損益保持不同欄位。
- 單筆股息先 floor；達 20,000 元門檻時扣 `floor(gross × 0.0211)` 二代健保補充保費；有效事件預設扣 10 元匯費。
- Portfolio 僅聚合每檔 Canonical Summary，不建立第二套公式。
- Golden Case `0050／價格 9.70／170 股` 的成交金額為 `1648`、手續費為 `2`、現金支出為 `1650`。

SaiETF 顯示層將 Canonical Core 的 `unrealizedProfit` 命名為「持有總損益」，將 `comprehensivePnL` 命名為「含息總報酬」。這只是欄位語意映射，不改寫核心公式。

### 4.3 移植驗證方法

- 從來源 commit 匯出固定 JSON Fixtures，禁止直接以 SaiETF 重新生成期望值。
- 同一 Fixture 同時送入 V3.7.8 TypeScript runner 與 SaiETF Kotlin Core。
- 成交金額、費用、稅、現金、股數、成本、已實現、未實現、清算價值、淨股息與組合加總逐欄完全相等。
- 覆蓋買入、整股、零股、定期定額、多次買入、部分賣出、清倉、股息、實際費用覆寫、實際稅額覆寫、現金與 00878 回歸案例。
- 任一差異即阻擋後續 UI、行情與 Release 工作；不得以容差忽略整數帳務差異。
- 移植完成後建立 SaiETF 自有 `CORE_LOCK.md`，記錄來源 commit、檔案雜湊、Fixture 雜湊與允許變更程序。

## 5. 資料模型與不可破壞規則

主要資料實體：

- `Account`：券商帳戶與使用者實際登錄的現金帳戶。
- `Instrument`：代號、中文名稱、簡稱、市場、類型與配息頻率。
- `LedgerEntry`：買入、賣出、股息、費用、稅費、現金與沖銷紀錄。
- `TaxFeeRuleSnapshot`：交易當時使用的 V3.7.8 費率參數、折扣、最低手續費與模式；公式順序固定。
- `HoldingLot`：每批買入來源、剩餘股數與成本。
- `ActualPortfolio`／`PortfolioAllocation`：真實庫存的策略分配。
- `ModelPortfolio`：不影響真實帳務的模擬組合。
- `QuoteSnapshot`：行情、來源、交易日、時段、來源時間、接收時間與品質狀態。
- `DailyAssetSnapshot`：每個台北交易日的成本、市值與各類損益。
- `DividendEvent`：公告、除息、基準、發放及入帳狀態。
- `SyncState`／`NotificationReceipt`：同步游標、錯誤、重試與冪等收據。

核心不變量：

- 帳務紀錄建立後不可覆寫或刪除；修正使用「沖銷＋新紀錄」。
- 台幣帳務結果使用整數；成交價輸入以固定尺度保存，但所有帳務輸出必須與 V3.7.8 `Math.floor` 結果完全一致。
- 手續費、費稅、成本、清算價值及股息只能由移植後的 Canonical Finance Core 計算。
- Portfolio 只加總已計算結果，不自行重算帳務。
- 同一標的可分配到多個實際組合，但分配股數總和不得超過真實庫存。
- 模擬組合永遠不計入總資產或真實庫存。
- 行情只影響估值，不能改寫帳本、成本或股息入帳。
- 總資產只包含庫存市值與使用者實際登錄的現金；不得自動創造現金。

## 7. 版面編輯器

版面編輯器入口位於「更多 → 頁面設定」。第一版支援總覽、組合、交易、股息及行情牆；系統設定頁本身不納入編輯。

操作結構：

1. 上方顯示與實際頁面同比例的真實預覽。
2. 點擊預覽中的框架或元件，以虛線選取框標示目前對象。
3. 下方顯示該元件可用的手風琴工具；預設收合，同一層只開一組。
4. 所有變更先寫入 Draft，使用「套用」才提交；「取消」捨棄 Draft；「重設」需二次確認。
5. 預覽必須使用與 Runtime 相同的 Renderer 與資料契約，禁止維護另一套假預覽。

元件能力：

- **框架**：顯示、排序、位置、寬高、內外距、對齊、圖層、鎖定、透明度、背景、邊框、圓角與陰影。
- **標題／文字**：內容、字級、字重、顏色、文字背景、行高、字距、換行、省略、水平／垂直對齊與動畫。
- **資料數值**：資料來源、欄位、格式、小數位、千分位、前綴／後綴及損益色。
- **圖片／圖示**：來源、填滿、適合、裁切、比例鎖定、大小與顏色。
- **圖表**：來源、系列、類型、顏色、損益色、線寬、資料點、標籤、圖例、座標軸、格線、Tooltip、十字線、縮放、平移、成本／現價／交易／股息標記。
- **提醒／跑馬燈／月曆**：規則、日期時間、條件顯示、方向速度、事件來源及事件狀態。
- 所有可設定顏色的項目都提供「跟隨損益色」；顏色與透明度分開設定。
- 數值位置與尺寸不得使用 `-1` 代表跟隨；自動尺寸使用明確模式欄位。
- 支援複製樣式與套用到相同元件類型，但不得複製資料綁定或帳務欄位來源。

儲存資料須經 Schema 驗證、數值範圍限制與版本遷移。錯誤設定回退到該元件預設值，不得造成頁面閃退。

## 8. 行情牆與專業圖表

首頁行情牆是主要模組，不是隱藏頁面。規格如下：

- 顯示持有標的的中文名稱／簡稱、代號、現價、漲跌、成交時間與資料狀態。
- 支援清單、精簡、進階與 Mini 圖表四種模式。
- 排序按鈕單擊切換升冪／降冪。
- 清單首欄固定「代號＋中文名稱」，其他欄位可水平滑動。
- 欄位、欄寬、行情牆高度、預設模式與 Mini 圖表顯示可設定。
- Mini 圖表呈現當日開盤至目前或收盤的走勢；下一交易日開盤建立新序列。
- 點擊標的進入完整標的頁，包含 K 線、OHLC、折線、面積、成交量、週期、縮放、十字線、庫存批次、交易紀錄與損益分析。
- 每個實際組合擁有自己的行情牆視圖，但價格必須來自同一行情中心。

## 9. 行情中心

資料流程固定為：

`來源轉接器 → 正規化 → Schema 驗證 → 交易時段／新鮮度判定 → 優先級選擇 → Room 快取 → UI`。

行情狀態包含：`REALTIME`、`DELAYED`、`CLOSED`、`CACHED`、`UNVERIFIED`、`UNAVAILABLE`。

規則：

- App 啟動或回到前景時立即更新一次。
- 盤中前景與可見浮動視窗的最低可選更新間隔為 1 秒。
- 每筆行情保存來源時間與接收時間；新交易日重置來源品質與優先級。
- 較舊的備援資料不得覆蓋較新的有效資料。
- 來源回傳空值、`-`、未成交或時段不符時，不可直接當成最新成交價。
- 來源失敗時採指數退避與熔斷；快取回退必須顯示原始時間與 `CACHED`。
- 首頁、標的頁、Widget、浮動視窗、損益與通知都讀取同一份選定行情。
- 提供行情診斷頁，顯示原始欄位、來源、驗證、拒絕原因與最終選定值。

官方公開資料用於收盤、歷史、交易日與參考資訊；即時來源採可插拔轉接器。若未設定可合法使用的即時來源，App 必須顯示延遲或收盤狀態，不得假稱即時。公開發佈前另行檢查 TWSE／TPEx 交易資訊授權條款。

## 10. 組合分析與建議

### 8.1 實際組合

使用真實庫存股數，計入總資產。顯示成本、市值、今日損益、持有總損益、已實現損益、股息、配置、歷史曲線與目標權重偏差。

### 8.2 模擬組合

使用自訂標的、投入金額與目標權重，不影響帳務。支援替換比較與 What-If 試算，例如比較 0050 與 006208 的配置、成本及歷史結果。

### 8.3 分析輸出

- 單一標的、ETF 類型、產業、主題與發行商集中度。
- 年化報酬、波動與最大回撤。
- 配息月份分布、預估年度現金流與空窗月份。
- 現況與目標配置偏差。
- 再平衡所需買賣股數、估計金額與費稅。
- 內容分成「資料事實、風險提示、可執行方案」。

第一版分析引擎在本機以可驗證規則執行，不將投資資料傳送到雲端，不自動下單。

## 11. 損益與每日歷史

- **今日損益**：目前持股數 ×（最新有效價－前一交易日收盤價）。
- **昨日損益**：上一個台北交易日保存的當日損益快照。
- **持有總損益**：目前持股市值－目前持股成本。
- **已實現損益**：賣出收入－對應成本－交易費稅。
- **股息收入**：實際入帳股息，獨立統計。
- **含息總報酬**：持有總損益＋已實現損益＋股息收入，必須明確標為含息。

昨日、今日、持有總損益是三個獨立指標。點擊總損益進入每日紀錄與區間統計，顯示日期、持股市值、成本、持股數量、各類損益與資料品質。

每日快照以 `Asia/Taipei` 交易日為鍵；同一天只能成功建立一次。收盤資料不完整時維持待完成狀態，禁止建立錯誤的最終快照。

## 12. 股息自動同步與月曆

股息狀態流程：

`預告 → 已公告 → 已除息 → 待發放 → 已入帳`。

App 自動追蹤目前持股、自訂組合及歷史待入帳標的：

- App 啟動或回到前景時立即同步。
- WorkManager 每日執行一次背景同步，另提供手動立即更新。
- 來源優先使用 MOPS 正式公司公告，再使用 TWSE／TPEx 除權息預告與 ETF 配息資訊。
- 預告資料可自動建立事件；正式公告後更新同一事件。
- 事件識別使用「代號＋股利年度／期別＋配息類型＋來源事件編號」，避免重複。
- 保存公告日、除息日、最後過戶日、停止過戶期間、股權／收益分配基準日、發放日、每單位金額與來源時間。
- 除息日、最後過戶日與基準日分開保存，不互相代替。
- 官方尚未公布的日期顯示「待公告」，不得推測。
- 公告修改時保存差異並通知使用者；同步失敗不得清空最後有效資料。
- 依除息資格日的庫存批次自動計算預估可領股數與金額。
- 官方更新不得覆蓋已確認的實際入帳金額。
- 即使標的已清倉，歷史股息仍永久保留。

月曆按月顯示預估、已確定與已入帳總額；使用者可新增尚未抓到的預告或建立覆寫，但必須標示「官方自動同步、使用者暫存、使用者覆寫、待官方確認」。

## 13. Android 系統介面

### 11.1 Widget

- 2×1：總資產、今日損益、更新時間。
- 4×2：指定組合、今日／持有損益與簡易走勢。
- 4×3：可選 3～6 檔的迷你行情牆。

Widget 採系統週期更新、使用者手動更新及 App 活躍時同步。Widget 不宣稱每秒即時，所有資料附更新時間與狀態。

### 11.2 浮動行情

- 使用者在可見 Activity 中主動授予 Overlay 權限並開啟。
- 顯示 1～5 檔，可拖動、縮小、展開與切換。
- 可設定 1／3／5／10 秒更新。
- 視窗可見期間使用前景服務與常駐通知；關閉後立即停止高頻輪詢和服務。
- 不從開機事件或任意背景狀態偷偷啟動。

### 11.3 每日損益通知

- 確認台灣交易日與有效收盤價後建立每日快照。
- 通知顯示總資產、今日損益、持有總損益與主要貢獻標的。
- 資料不完整時顯示待完成，不先發錯誤金額。
- 同一交易日以收據表保證最多發送一次。
- 可設定時間、隱藏金額、只顯示百分比及週末行為。

## 14. 備份、安全與權限

備份使用單一 `.saietf` 加密封裝，包含資料庫、設定、Schema 版本、App 版本、建立時間、資料筆數與 SHA-256。密碼只由使用者持有。

還原流程：格式與雜湊驗證 → 預覽差異 → 選擇合併或取代 → 建立回復檢查點 → 還原 → 重算庫存與損益 → 驗證；任何階段失敗都整筆回滾。

權限採即時請求：

- 網路：行情與公告。
- 通知：啟用通知時。
- Overlay：啟用浮動行情時。
- 檔案：透過 Storage Access Framework 匯出／匯入。

不要求聯絡人、簡訊、通話、位置或相簿權限。資料庫加密金鑰由 Android Keystore 保護。診斷匯出必須移除備註、金額及其他敏感資料。

## 15. 錯誤處理

- 所有頁面具備載入、空白、離線、部分成功與錯誤狀態。
- 行情、股息、備份與通知錯誤不得轉成成功提示。
- 網路失敗使用有限次重試與指數退避。
- DB 寫入、還原、每日快照及通知使用交易或冪等鍵。
- App 異常終止後能從最後已提交狀態恢復，不留下半筆交易、半次還原或重複通知。
- 本機保留去識別化診斷紀錄，使用者可檢視與主動匯出。

## 16. 測試與 Release Gate

每次推送到 `main` 必須執行：

1. Kotlin 編譯、Lint 與靜態分析。
2. V3.7.8 雙引擎 Golden Fixtures、帳務、費稅、庫存、損益、組合分配、行情新鮮度、股息合併及備份的單元測試。
3. Room Schema 與 Migration 測試。
4. Compose 導航、交易流程、股息月曆、版面編輯器 Draft／Apply／Cancel／Reset 與錯誤狀態測試。
5. Android 10、12、14、15、16 代表性 Emulator 流程測試。
6. Widget、Overlay、通知、背景限制、離線與程序重啟測試。
7. 產出 QA APK、SHA-256、測試摘要與 SBOM。

任何下列情況禁止建立 Release：

- 測試、Lint、Migration 或 APK 安裝失敗。
- 版本資訊與檔名不一致。
- 帳務或損益固定案例不符。
- Kotlin Core 與 V3.7.8 TypeScript Fixture 任一欄位不一致，或 `CORE_LOCK.md` 雜湊不符。
- 版面預覽與 Runtime Renderer 不一致，或無效設定造成頁面閃退。
- 行情牆、標的頁、Widget、浮動視窗或通知出現不同選定價格。
- 股息同步重複建立事件或覆蓋實收金額。
- 備份損壞仍寫入資料庫。
- 機密、API Key 或簽署憑證出現在 Repo／APK。

開發階段的「不送審核」代表不建立 PR、不等待人工核准、不送商店審核；不代表跳過自動測試、驗收 Gate 或 APK 安裝驗證。
